## Bot identity direction and delegated work

P1 owner-directed design exploration. The owner dislikes the current abstract Bot marks, is unsure about calling the new identity system “pets,” and wants ten strong pre-made identities for small-business owners. Keep the BotBound company logo separate from individual Bot identities. Create original BotBound-owned art; do not reuse ChatGPT Pets assets. The Pets plugin is for companions inside ChatGPT Work mode, exposes no BotBound runtime/API, and instructs that it not be used for other apps. Redistribution rights are not established.

Current code stores one `mark_key` per Bot (`src/db/schema-base.ts`, `src/lib/bot-mark.ts`) and presents a Symbol/Color picker (`src/components/BotMarkPicker.tsx`). Fifteen motifs × eight palettes create 120 stable identity keys; a database check, allocator trigger, unique index, and capacity helper use that set. The owner’s 10-item visual catalog is feasible, but the current uniqueness/capacity coupling must be redesigned so distinct Bots can reuse a character when appropriate. Do not introduce a universal 10-Bot account limit based on a market assumption. Any database migration is authored and reviewed here, then applied by the owner by hand; never update the database automatically.

If BotBound adds delegated subagents, model them as temporary runtime workers owned by a main Bot, not as separate customer-facing Bots, rows, seats or identities. They should inherit the parent identity and permission ceiling, may receive narrower scoped permissions, and must send every external action through the existing consent, approval, audit and idempotency gates. Use them only for multi-step work where they improve the result; routine work should remain one Bot action. Keep their orchestration invisible unless an owner needs a concise activity record. This is a future architecture rule; current source contains no subagent runtime.

The design exploration will compare three directions for an initial ten-item catalog, grounded in BotBound’s ink/paper and violet system and the owner’s low-chrome ChatGPT Desktop reference. Static art is the default; motion must be subtle, tied to real activity and reduced-motion safe. Do not build the identity catalog until the owner chooses a direction.
