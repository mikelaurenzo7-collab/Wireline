## Part A — Database / data integrity

### A0. Corrected finding: the database is HEALTHY (no incident)

Initial `npm run db:drift` reported many `[journalled]` "missing" objects, which looked like an incident. Read-only verification against the live catalog resolved every one:

| Drift-reported "missing" | Actual live state | Verdict |
| --- | --- | --- |
| `wireline_cloned_voices`, `wireline_pronunciation_dictionaries`, `wireline_fleet_tasks`, `wireline_xai_phone_bindings` | `to_regclass` = absent | **Intentionally retired** — dropped by 0169/0172 and earlier retirement migrations. |
| `wireline_team_members.tenant_isolation` policy | table present, RLS enabled, policies `workspace_read/insert/update/delete` | **Policy renamed** to `workspace_*`; `workspace_read` correctly keys on `wireline_current_user_id()` (tenant GUC). |

The drift parser only sees `CREATE` text, not later `DROP`/rename — so it flags retired/renamed objects as "drifted". **No missing production objects.** All 83 `wireline_*` tables have `rowsecurity = true`.

Consequence: `FORCE ROW LEVEL SECURITY` is safe to author as an enhancement (all tenant tables already carry a `wireline_current_user_id()` policy), but it is **not** an emergency fix and must still be its own reviewed change (owner/system-path access needs an explicit bypass role or policy before forcing).

### A1. Spend-reservation leak (code-only, safe — do first)

- `src/middleware/audit-middleware.ts:493-500` sums all `audit_log.cost_usd` for the period, including rows stuck at `accounting_state = 'reserved_before_provider'` (worker froze between reserve and outcome). One crash permanently inflates the hard monthly cap.
- Fix: exclude `reserved_before_provider` rows older than `STALE_RESERVATION_TTL_MINUTES = 30` from the MTD sum. In-flight reservations still count against concurrent overshoot; abandoned ones drop out.
- Add a targeted test.

### A2. Drizzle schema reconciliation (code-only, no DDL)

- `schema.ts` re-exports `schema-base`/`voice-usage-schema`/`resend-webhook-schema` but **not** `security-schema.ts`; `drizzle.config.ts` feeds only `schema.ts`. `db:generate` therefore can't see `wireline_users.session_revoked_before`/`session_version` (0120/0127) or `wireline_team_members.invitation_*`/`accepted_at`, and would plan `DROP COLUMN`.
- Fix: re-export `security-schema.ts` from `schema.ts`, dedupe the triple-defined `wireline_subscriptions` (`schema.ts`, `schema-base.ts`, `security-schema.ts.subscriptionEntitlements`), and verify `npm run db:generate` yields an empty/intended-only diff against the newest snapshot. `tests/migration-journal-integrity-contract.test.ts` must stay green.

### A3. FK contradiction (append-only migration; verify live FK names first)

- `0015_add_fk_constraints.sql` used `ON DELETE SET NULL`; `0039_tenant_user_id_not_null.sql` made the same columns `NOT NULL`. A direct `DELETE FROM wireline_users` raises 23502.
- Fix: new migration converting remaining `SET NULL` user FKs to `ON DELETE CASCADE` (mirroring 0160/0162) and dropping the legacy competing FK on `wireline_team_members`.
- Precondition: read-only probe of live `pg_constraint` to enumerate exact FK names (do not assume 0015 names survived).
- Apply via `scripts/promote-production-schema.mjs` after exact-head green — never manual `db:migrate`.

### A4. FORCE ROW LEVEL SECURITY (separate reviewed change)

- Author a migration adding `FORCE ROW LEVEL SECURITY` to tenant tables, with an explicit owner/system-path bypass (role or policy) audited against `docs/DATABASE_OPERATIONS.md` "RLS and privilege verification".
